# 不同类型论文的拆解侧重点

根据论文所属类型，在通用工作流基础上补充以下关键维度；若论文兼具多种属性（如“新 Benchmark + 新基线模型”），按实际侧重组合使用，不强行套用无关条目。

---

## 1. Benchmark / Dataset 论文

核心目标：解释它**为什么必须这样设计**，而不是只介绍“提出了一个数据集”。

重点拆解：
1. **目标能力**：要评估什么核心能力？
2. **现有盲区**：已有 Benchmark 具体漏掉了什么，或为什么会高估模型能力？
3. **任务与维度划分**：任务如何分类，各能力维度之间是什么关系？
4. **数据/环境构造**：样本从哪来、如何标注或生成、有哪些过滤与质检机制？
5. **输入输出与评估协议**：模型接收什么输入、输出什么格式、如何打分？
6. **指标含义**：各指标如何计算、为什么适合衡量该任务？
7. **防投机与防泄漏设计**：若包含多层评估、视觉随机化、遮挡、反事实样本、OOD 测试或防数据泄漏机制，需说明每一项具体排除了哪种“投机解题路径”。
8. **诊断结论**：评测结果暴露了当前模型在哪些具体能力上的缺口？

---

## 2. 方法 / 模型论文

核心目标：讲清楚**方法为什么有效**，以及实验是否真正验证了这一机制。

重点拆解：
- **整体架构与数据流**：核心模块如何衔接，信息如何流动。
- **训练 vs. 推理分离**：分别梳理训练目标/损失函数与推理时的实际执行流程，避免混为一谈。
- **与 Baseline 的本质差异**：改进究竟发生在表征、结构、训练目标、数据还是推理策略上？
- **消融验证**：消融实验是否逐一证明了核心模块的必要性？
- **代价与边界**：计算开销、数据依赖和适用边界（论文未说明的不要脑补）。

---

## 3. Agent 论文

核心目标：除了底层模型，重点讲清 **Agent 与环境的交互闭环**，遵循论文真实设计，不为了凑齐流程图而强行补全原文没有的模块。

优先梳理以下交互链路（如论文不同则按论文真实流程）：

`观察（Observation） → 状态理解 → 推理 / 规划 → 动作执行 → 环境反馈 → 下一轮决策 / 终止判定`

重点拆解：
- **感知与状态**：Agent 接收什么观察或环境状态？
- **推理与工具**：如何规划决策？可调用哪些工具或动作空间？
- **反馈与循环**：环境如何反馈？是否包含记忆、反思（Reflection）、重规划或多轮交互？
- **终止与成功标准**：任务何时结束，如何判定成功？
- **能力边界定性**：明确区分以下层级，**不要把所有带 LLM 与工具调用的系统笼统称为“具备自主学习能力的 Agent”**：
  - 仅生成单次动作计划；
  - 调用工具执行动作；
  - 根据环境反馈动态调整策略；
  - 具备长期记忆或跨任务持续学习能力。

---

## 4. Survey / Review 论文

核心目标：建立清晰的**领域地图**，而不是逐段翻译原文。

重点拆解：
- **分类体系（Taxonomy）**：提炼作者划分研究脉络的核心维度与分类框架。
- **类别边界与代表工作**：解释各类别的定义边界、典型方法及其适用场景。
- **路线对比**：总结不同技术路线的核心取舍与优缺点。
- **开放问题**：整理作者明确指出的领域挑战与未来方向。
- **来源标注**：明确区分“综述作者的归纳判断”与“具体原论文的实验结论”。
